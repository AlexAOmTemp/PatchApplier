## 1. Зачем

Сейчас GUI не имеет **никакого file explorer**. Раньше он был встроен в диалог `open_settings_dialog` — вместе с деревом политики, обоими сразу. Диалог заменён на заглушку (7.1), старое дерево удалено. Пользователь видит главное окно, может применять патчи и открывать File → Project settings, но **не видит структуру каталогов проекта**.

7.3 закрывает это: **дерево каталогов в главном окне**, вкладка на root, read-only.

## 2. Только каталоги, без файлов

**Решение:** дерево показывает **только каталоги**. Файлы не показываются никогда.

**Почему:**

- **Наследование policy.** `PathPolicy` на каталоге действует на всё поддерево. Пользователь ставит «выключить `docs/generated`» один раз, а не для 200 файлов. Per-file управление — вырожденный случай, нет реального сценария.
- **Шум.** Каталог с 1000 файлов невозможно просматривать без полного file-browser (виртуализация, поиск, фильтры). Это отдельная большая задача, не 7.3.
- **Так было раньше.** Старое дерево в `open_settings_dialog` показывало только каталоги и работало. Никаких жалоб от пользователя не было.

**Как следствие:** дерево — плоский список каталогов с отступами (или вложенный, если каталоги вложены), без раскрытия/закрытия. Все каталоги видны сразу. Если их больше 100 — вкладка с прокруткой.

## 3. Что показываем

**Вкладка на каждый root.** Root'ов в workspace может быть несколько (basename уникален). Каждый — своя вкладка в правой панели (сейчас там Настройки, Получить дифф, Стартовый текст).

Заголовок вкладки = basename root'а. Внутри — дерево каталогов:

```
toolkit/
├── code/
│   ├── bridge/
│   ├── manual/
│   └── toolkit/
│       ├── backends/
│       ├── config/
│       ├── core/
│       ├── formats/
│       ├── indexers/
│       ├── runner/
│       ├── tests/
│       └── tools/
├── docs/
└── runtime/
    ├── logs/
    └── state/
```

**Глубина** — по умолчанию 3 (как было раньше в `scan_subdirs`). Может быть настраиваемая; см. §7 вопрос 3.

**Скрытые каталоги** (`.patch_applier`, `.git`, `__pycache__`) — **не показываем** по умолчанию. Отдельная галка «show hidden» — открывает их, серым.

## 4. Что не в 7.3

- **Файлы.** Принципиально — только каталоги (см. §2).
- **Редактор per-path policy через дерево.** Это отдельный шаг — редактор внутри Project settings, использует те же данные (`scan_subdirs`), но с флагами.
- **Drag-and-drop, переименование, удаление.** Read-only.
- **Открытие файла в Studio.** Roblox-код живёт в DataModel — отдельный режим.
- **Поиск по дереву.** При 100 каталогах справляется Ctrl+F браузера.

## 6. Как читает данные

**`loader.scan_subdirs(root, max_depth=3, patterns, show_hidden)`** — уже есть в `config/loader.py`. Возвращает `[(rel_path, is_hidden)]`.

Для каждого root'а:

```python
scan_subdirs(fb._root, max_depth=3, patterns=self._patterns, show_hidden=show_hidden)
```

`fb` — внутренний `FilesystemBackend` корня. `self._patterns` — `.patchignore` из `state_dir` (уже загружен в `WorkspaceBackend.open`).

**Обновление.** При открытии сессии — `refresh()`. Ручная кнопка `↻` в заголовке вкладки. Авто — см. §7 вопрос 4.

## 7. Открытые вопросы

### 1. Где в UI — правый panel или новый док?

**Предлагаю правый panel** (там сейчас `Старт сессии` + `Настройки`). Добавить блок `Файлы` сверху или снизу.

**Альтернатива:** новый док-панель (снизу, как в IDE). Больше места, но layout надо менять.

### 2. Один tree на все roots или вкладки?

**Вкладки** (по образцу Project settings). Каждая — свой `ttk.Treeview`. Плюс — изоляция. Минус — место под tab bar.

**Один tree** с двумя top-level «toolkit» и «other». Визуально тоже читаемо, но если два root'а похожи (`src1`, `src2`) — путаница.

**Предлагаю вкладки.**

### 3. Глубина по умолчанию и настройка

Сейчас `scan_subdirs` по умолчанию `max_depth=2`. Для `toolkit/` этого мало — не увидим `toolkit/code/toolkit/tools/`.

**Предлагаю `max_depth=3`** (видно до `tools`, не до `manual/unit_proto`).

**Настройка** — галка в UI (`max_depth` 2/3/4) или фиксировано? Предлагаю фиксировано на 3, настраиваемое — если попросят.

### 4. Автообновление при write

Когда файл или каталог создаётся/удаляется через патч, дерево должно обновиться. Триггер — успешный write в корень.

**Предлагаю авто** — `Session.apply_patches` возвращает results, `app.py` фильтрует, обновляет вкладки. Дёшево (у нас уже есть router для этого).

**Альтернатива:** кнопка `↻` только вручную. Проще, но пользователь должен помнить нажимать.

### 5. Где живёт state активной вкладки?

**Предлагаю `CONFIG`** (`ui_active_root: "toolkit"`). Сохраняется при закрытии, восстанавливается при старте.

### 6. Клик на каталог — что делает?

Варианты:
- **(a)** Ничего — только просмотр.
- **(b)** Копировать путь `<basename>/<rel>` в буфер (для LLM: пользователь копирует и вставляет в патч).
- **(c)** Открыть каталог в системном explorer.
- **(d)** Раскрыть/закрыть (но у нас плоский список, нечего раскрывать).

**Предлагаю (b)** — дёшево, полезно. Двойной клик — то же самое (копировать), для совместимости с браузерным поведением.

## 8. Что **не** в дизайне

- Files (только каталоги).
- Multi-select, drag, inline rename.
- Поиск.
- Preview каталога (список его файлов).
- Показ MCP-стороны (`ReplicatedStorage.X.Y`) — отдельная нотация.
