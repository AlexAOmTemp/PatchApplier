# Тестовая сессия — проверка unit-модели

Ты работаешь с **новым инструментом** `read_unit` (черновик). Инструмент даёт доступ к содержимому файлов проекта через **единый адрес**, независимо от формата: Python, Luau, markdown.

## Модель

Полная спецификация — `MODEL.md` в этой папке. Кратко:

**Unit** — именованная сущность. Бывает `module`, `function`, `method`, `class`, `section`.

У unit'а три **части**:
- `head` — объявление (`def foo(a):`, `class Foo:`, `function f(x)`, `## 3.1 Title`).
- `annotation` — короткое описание (Python docstring, Luau `--[[ ]]` / `---`, markdown `<!-- summary -->`). Может отсутствовать.
- `body` — тело (всё после head и annotation).

`part="all"` (по умолчанию) — весь unit целиком.

**Адрес** — JSON-объект:
- `{"qualname": "Foo.bar"}` — Python/Luau; `{"qualname": "<module>"}` — модуль;
- `{"section_number": "3.1"}` или `{"section_title": "Format"}` — markdown.

При неоднозначности добавляется `occurrence` (номер сверху вниз).

**Blocks** — нумерованные элементы внутри body. Для функции — top-level statements; для класса — методы и атрибуты; для секции — подсекции. Адрес: `block=3` или диапазон `block="1-5"` или список `block="1,3,7-9"`.

`part` и `block` вместе не используются.

## Инструмент

`python cli.py FILE [ADDRESS] [--part ...] [--block ...]`

- `--list` — список всех unit'ов в файле (адрес + kind + line-range + число блоков).
- `--dump` — полное дерево с частями и блоками.
- Без опций — нужен `ADDRESS` (JSON-строка).
- `--part head,annotation` — выбрать части (через запятую). По умолчанию `all`.
- `--block "1-3"` — выбрать блоки. Можно диапазон, список, отдельные числа.

Пути к файлам — **относительно `toolkit/code/`** (там же, где ты запускаешь cli). Например: `toolkit/core/patcher.py`. Файлы **вне** `code/` доступны через `..`: документация живёт в `toolkit/docs/`, то есть от `code/` это `../docs/REQUIREMENTS.md`.

Ответ — либо текст, либо ошибка в stderr:
- `not_found` — адрес не найден;
- `ambiguous` — несколько совпадений, нужен `occurrence`;
- `block_out_of_range` — блок больше, чем есть в body;
- `not_applicable` — `block` в head или annotation;
- `bad_part` / `bad_block` — плохой аргумент.

## Что тестируется

1. **Понимание модели.** Можешь ли ты правильно адресоваться: назвать unit, part, block по описанию задачи.
2. **Предсказуемость.** Одинаковая задача на разных форматах должна решаться одинаково.
3. **Ограничения модели.** Где модель **не** может достать — и понимаешь ли ты почему (см. `MODEL.md` §5).

Тебе **не нужно** читать файлы через `read_file` или `grep`. Только `read_unit` через CLI — чтобы проверить именно модель.

## Как работать с CLI (важно)

Ты **не запускаешь** команды сам. У тебя нет доступа к терминалу. Пользователь в чате выполняет команды вручную и присылает тебе вывод.

**Формат взаимодействия:**

1. Ты пишешь **блок команд** — от одной до пяти. Оборачивай их в один ``` код-блок. Формат:

   ```
   cli.py FILE [ADDRESS] [--part ...] [--block ...]
   ```

   Пользователь запустит их из директории `toolkit/code/` — то есть `cli.py` для него это `python manual/unit_proto/cli.py`, а `FILE` — путь относительно `toolkit/code/`. Пример реальной команды:

   ```
   python manual/unit_proto/cli.py toolkit/core/patcher.py '{"qualname": "Patcher._apply_one"}' --part head,annotation
   ```

   **Важно про PowerShell.** Пользователь запускает команды в PowerShell. JSON-адрес должен быть в **одинарных кавычках**, а внутренние двойные кавычки — **экранированы обратным слэшем**: `'{"qualname": "Foo.bar"}'`. Другие формы (двойные кавычки, `--%`, `cmd /c`) не работают — PowerShell ломает JSON. Всегда давай адрес именно в этой форме.

2. Пользователь выполняет и присылает блок с результатами — stdout или stderr для каждой.

3. Ты анализируешь и либо пишешь следующий блок, либо заканчиваешь.

**Почему батчами:** один вызов — это долгий round trip. Пять команд за раз — пять задач за один шаг. Если следующая команда зависит от предыдущей (например, номер occurrence), выделяй её в отдельный блок и жди.

**Правила:**

- Не пытайся «представить» вывод — ты его не знаешь. Пиши команду и жди.
- Не используй `read_file`, `grep`, `cat` — только `cli.py`.
- Если команда ошибочна — пользователь пришлёт stderr, ты поправишь.
