407: '**`CompositeBackend._state` и смерть суббекенда.** `is_alive = any(sub.is_alive())` — правильный контракт (degraded = поддержанное состояние). Но `backend_state(name)` читает `_state[name]`, который обновляется только через `_set_state` (вызывается из `open` / `close` / `reopen`). Если MCP-процесс умер сам — `backend_state("mcp")` продолжает врать «ready». Сейчас это не критично: GUI опрашивает per-backend state и переоткрывает MCP сам при следующем патче. Варианты: (a) периодический sync `_state` с `sub.is_alive()`; (b) subscription — суббекенд уведомляет композит о смерти; (c) не менять — считать `is_alive` ответом на «стоит ли пробовать», а точный per-backend state получать у самого суббекенда. Скорее всего (c) достаточно.\r\n'
